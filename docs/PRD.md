# PRD: 꼬맨틀 솔버

- 작성일: 2026-09-23
- 상태: 프로토타입 완료 (https://komantle-solver.mmmn.workers.dev)
- 작성 방식: pm-skills PRD 템플릿(문제 → 목표 → 사용자 → 기능 → 비목표 → 지표) 기준

## 1. 한 줄 요약

꼬맨틀(한국어 단어 유사도 추측 게임)에서 막힌 사용자가 첫 화면의 숫자 3개와 자신이 추측한 단어를 넣으면, 정답 후보와 "조금 더 유사한 단어" 힌트를 받아 스스로 정답에 가까워지도록 돕는 정적 웹 도구.

## 2. 문제 정의

- 꼬맨틀은 하루 한 단어를 맞히는 게임인데, 유사도 점수만으로는 방향을 잡기 어려워 수십 번 추측하다 포기하는 사용자가 많다.
- 정답을 그냥 알려주는 커뮤니티 스포일러는 게임의 재미를 없앤다. "정답을 주지 않고 방향만 알려주는" 중간 단계 도움이 없다.
- 기존 도구는 서버나 외부 API에 의존해 유지비가 들거나, 꼬맨틀 사이트를 크롤링해 불안정하다.

## 3. 목표

| 구분 | 내용 |
|---|---|
| 목표 | 사용자가 정답을 직접 맞히도록 힌트 강도를 조절해 돕는다 |
| 목표 | 서버·외부 API 없이 브라우저만으로 동작해 무료로 운영한다 |
| 목표 | 새 회차 데이터를 붙여넣는 것만으로 즉시 사용 가능하게 한다 |
| 비목표 | 정답을 바로 공개하는 "치트" 기능 |
| 비목표 | 로그인, 기록 저장, 랭킹 등 커뮤니티 기능 |
| 비목표 | 꼬맨틀 사이트 자동 연동(크롤링) |

## 4. 대상 사용자

- **주 사용자**: 꼬맨틀을 매일 하지만 30번 이상 추측해도 방향을 못 잡는 캐주얼 플레이어.
- **부 사용자**: 단어 임베딩·유사도 계산에 관심 있는 개발자(소스 공개).

## 5. 사용자 시나리오

1. 사용자가 꼬맨틀 첫 화면의 1위·10위·1,000위 유사도 숫자 3개를 복사해 솔버에 붙여넣는다.
2. 솔버는 미리 계산한 지문(fingerprint)과 대조해 정답 후보를 좁힌다.
3. 사용자가 이미 추측한 단어와 그 유사도를 단서로 입력하면 후보가 더 좁혀진다.
4. 힌트 강도(조금·보통·많이)를 고르면 입력한 단어보다 순위가 더 높은 단어를 힌트로 보여준다.
5. 사용자는 힌트를 꼬맨틀에 입력해 스스로 정답에 도달한다.

## 6. 기능 요구사항

| # | 기능 | 우선순위 | 상태 |
|---|---|---|---|
| F1 | 숫자 3개 붙여넣기로 정답 후보 탐색 | P0 | 완료 |
| F2 | 추측 단어 + 유사도를 단서로 입력해 후보 좁히기 (어휘 59,118개 벡터 대조) | P0 | 완료 |
| F3 | 힌트 강도 3단계 (조금: 순위 3/4, 보통: 1/2, 많이: 1/5 지점) | P0 | 완료 |
| F4 | 정답 확정/미확정 상태 표시, 힌트 입력이 자동 단서가 됨 | P1 | 완료 |
| F5 | 전체 초기화, 새 회차 붙여넣기 시 자동 초기화 | P1 | 완료 |
| F6 | 모바일 화면 대응 | P1 | 완료 |
| F7 | 오늘의 회차 자동 인식 | P2 | 미정 |

## 7. 비기능 요구사항

- 서버 코드 없음. 모든 계산은 브라우저에서 정적 파일로 수행.
- 외부 API·크롤링 없음. 꼬맨틀 사이트에 부하를 주지 않음.
- 데이터 약 135MB는 Cloudflare Workers Static Assets에 배포, 무료 플랜 범위 내 운영.
- 로직은 Node 테스트(`npm test`)로 검증.

## 8. 기술 개요

- 프론트: 순수 HTML/JS/CSS (`komantle/web/`)
- 데이터 생성: Python, FastText 한국어 벡터 → 이웃·지문 사전 계산 (`precompute.py`, `export_web_data.py`, `export_vectors.py`)
- 배포: Cloudflare Workers (솔버), Vercel (소개 페이지, Next.js 16)

## 9. 성공 지표

| 지표 | 목표 |
|---|---|
| 힌트 사용 후 정답 도달률 | 80% 이상 |
| 정답 도달까지 추가 추측 횟수 | 평균 10회 이하 |
| 페이지 로드 후 첫 결과까지 시간 | 3초 이내 |
| 월 운영 비용 | 0원 |

## 10. 리스크 및 열린 질문

- 꼬맨틀이 사용하는 단어 벡터가 바뀌면 사전 계산 데이터를 다시 만들어야 한다.
- 힌트가 너무 강하면 "치트"가 되고, 너무 약하면 쓸모가 없다. 3단계 기준값은 사용자 피드백으로 조정 필요.
- 과제 요구사항(로그인·CRUD·지도·결제)과 솔버를 어떻게 하나의 서비스로 묶을지 미정. (`docs/PLAN.md` 참고)
